# 差异清单：市况台 vs 原站（REA 实证送审稿）

> 性质：主聊天按 REA 实测结论整理的**提案送审稿，非规格**。是否立项、优先级、形态一律待架构裁定并写入 SPEC 后才可实现；观测台 UI 冻结期内本清单任何一条都不动代码。
> 证据：原站侧 = REA 实测（证据文件 `~/workspace/rea-lab/`，研究笔记 `docs/REA-ANALYSIS-aisafetyhot.md`）；本站侧 = 2026-10-17 代码实查 `~/workspace/aihot-finance`。

## G1 知识层缺失（大）

- **原站**：`/papers` 论文库约 2,430 篇，十余维细粒度筛选；`/conferences` 八大顶会（ICLR/ICML/NeurIPS/ACL/IEEE S&P/USENIX/ACM CCS/NDSS）按会议×年份组织；论文详情含「论文速读」（问题/方法/实验/局限）+「深度解读」六问；公开接口有 `/api/v1/papers`。
- **本站**：web 路由无 papers/conferences（`apps/web/app/routes/` 实查）；contracts 无 paper 相关字段（grep 0 命中）；47 个冻结信源中无论文类来源。
- **差距**：整层产品面缺失，不只是 UI。
- **提请裁定**：财经站的对应物应是「研报/财报/研究层」而非照搬 AI 论文库——先定这一层在市况台是什么，再谈信源（涉及信源冻结是否开口子）与实现。建议排 S2 之后候选。
- **【架构裁定 2026-10-17：缓办，挂起待用户拍板】** 定性为产品范围扩张（新增模块 + 破 47 信源冻结），超出架构自决范围，归用户在 S2 末「第一周周报 + UI 解冻清单」时一并拍。架构意见记录：财经版对应物应是研报/研究层而非照搬论文库，判断成立；但点火与第一周调味完成前不开口子，信源冻结不破。在此之前只许在本文档攒候选研报源名单，不许接入。

## G2 搜索机制：异步任务 vs 同步查询（中）

- **原站**：`POST /api/site/search/query {q}` 拿 id → 每 1 秒轮询 `GET /api/site/search/query/{id}` 至 state 非 pending（约 45 次上限），`/all/search-busy` 为等待态。
- **本站**：无 search/query 接口（grep 0 命中）；搜索走 pool 同步查询，仅 `/api/site/search/suggestions` 联想；`search-busy.tsx` 路由文件存在但无对应异步后端。
- **差距**：数据量小无感；收录上万后，同步搜索的延迟与超时风险上升，原站方案更稳。
- **建议**：低优先，以 S2 巡检的搜索耗时数据触发再议。
- **【架构裁定 2026-10-17：缓办，数据触发】** S2 巡检加一项：记录搜索实际使用频次与耗时。触发线：搜索 p95 >2 秒或用户明确抱怨慢，居一即立项改异步（POST query + 轮询 + busy 态）。没数据前同步实现保留，不预先重构。

## G3 河流数据口径：周期快照 vs 实时计算（中）

- **原站**：03 河流走独立接口 `GET /api/site/overview`，返回 sources[102]/topics[50]/cards[197]/coverage 覆盖统计；实测快照时间为抓取日 3 天前、下次刷新在抓取当日——**周期性快照**，非实时。
- **本站**：river 嵌在 `/api/site/monitor` 响应内（`packages/backend/src/site/monitor.ts`：river{sources, flows}），每次请求实时计算；无 overview 接口（grep 0 命中）。
- **差距**：原站用快照换性能与呈现稳定；本站实时算在当前数据量下没问题，量大后 monitor 响应体积与耗时会涨。
- **建议**：S2 巡检记录 monitor 响应体积/耗时，数据说话再裁，不预先改。
- **【架构裁定 2026-10-17：缓办，倾向保留本站实时口径】** 原站周期快照实测滞后 3 天，那是原站的弱点不是要抄的规格；本站实时算先天更新鲜。S2 记录 monitor 响应体积与耗时，若成为真实负担再议改快照或混合（快照兜底+增量）。裁定前维持现状。

## G4 材料扫描流分页（小）

- **原站**：`GET /api/site/monitor/feed?cursor=` 独立分页（nextCursor）。
- **本站**：monitor 一次返回 feed{items}（FEED_LIMIT 截断），无独立 feed 接口（grep 0 命中）。
- **建议**：与 G3 一并观察，量触发再改。
- **【架构裁定 2026-10-17：与 G3 并案观察】** 触发线：真数据下 feed 条数常态超过 FEED_LIMIT 或 monitor 载荷明显拖慢首屏，居一即立项 cursor 分页。S2 巡检一并记录。

## G5 话题详情页形态（小，非功能缺失）

- **原站**：`/topics/:slug/page/:page` 路径式分页 + 话题筛选流。
- **本站**：话题页存在且可分页（`apps/web/app/routes/topic.tsx`，`?page=` 参数 + DayList/Pagination），形态为词条页，与原站筛选流观感不同。
- **建议**：记录备查；UI 冻结期内不动，不单独立项。
- **【架构裁定 2026-10-17：不做，关闭】** 功能等价、仅路径形态差异，属化妆级；将来 UI 解冻若用户点名再议。

## G6 运营面差异（小）

- **原站**：`/board` 留言板（留言/Issue/下架/更正/推荐来源）、`/newsletter` 订阅 + confirm/unsubscribe 完整流。
- **本站**：feedback 页，无订阅流。
- **建议**：市况台为自用站，不跟，备查。
- **【架构裁定 2026-10-17：不做，关闭】** 个人情报控制台无订阅受众，feedback 页足够；除非用户亲自提出，不再议。
