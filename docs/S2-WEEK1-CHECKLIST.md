# S2 第一周调味清单（施工总包自备，UI 冻结期执行）

阶段口径：S1 关单后进入 S2 第一周。UI 冻结——只修缺陷、不重设计；本清单由主聊天每日推进，用户只在第 7 天周报时定 UI 解冻清单与 G1 研报层。

## 每日巡检（每天一次，数字留痕）

- 采集：当日 articles 新增、直采 42 源各自成功/失败、推送 16 源入库数。
- 分析链：analyses 成功率、404/限流计数、eligible publications 数；翻译：title_zh 覆盖率、translate-headlines 批次 receipts 是否 completed、25% 子上限是否触顶。
- 出口：/api/site/pool total 与 today、monitor topics/feed 条数、日报是否 08:00 准时出刊。
- 观察项（架构 S2 新增）：站内搜索频次/耗时、monitor 响应体积/耗时、feed 条数 vs FEED_LIMIT。

## 逐源体检（第一周内逐个过完 58 源）

- 直采源：连续 3 天零入库的源单独查因（源站改版/被墙/解析坏）。
- 推送源重点三家：
  - SCMP 两 feed：Mac 普通请求直连的量是否稳定（目标各 ~50/次）。
  - 巴伦：四路（普通→curl_cffi 指纹→stealth→dynamic）仍全 403 的话，记为长期缺口候选，带证据报架构。
  - 雪球：patchright 预热在 Mac 的首跑结论（xq_a_token 是否种下、接口是否 200）；失败则把日志留全再定方案。
- 讨论源（股吧/雪球/HN）：只核 hot_signal 是否只供热点证据、未单独成条。

## 精选校准（攒样本，不凭感觉改门槛）

- 每日抽 pass/block 各若干条人工判读：该过的有没有被压、荐股喊单类 sig 是否 ≤2、有没有噪声混进精选。
- 译文质量：抽 titleZh/summaryZh，看未译残留片段（如「defiance gravity」式中英夹生）、标题党式改写是否过度；只记录样本与比例，改提示词须攒够证据再送审。
- 门槛数字调整按 docs/selection.md 用标注样本校准，不临场拍数字。

## S1 补账（Mac rebuild 后随手结清）

## 第 7 天周报（交付物）
