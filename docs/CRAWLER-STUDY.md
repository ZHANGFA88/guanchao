# 爬虫学习沉淀（CRAWLER-STUDY）

> 后端组学习输出（2026-10-17 立项，第一批接入实证后成稿主体）。目的：把「能抓」升级为「抓得稳、可诊断、可恢复」。每条结论尽量挂本站实证，无实证的标。

## 1. 反爬指纹与封禁面（课题一）

- **TLS/JA3-JA4 与 HTTP/2 指纹**：服务端可按 ClientHello 与 H2 帧序识别非浏览器客户端；本站对策是推送器分级升级链——普通请求 → curl_cffi（chrome 指纹伪装）→ StealthyFetcher（Camoufox）→ DynamicFetcher（2026-10-17 Mac 实证定版，见 push-scrapling.py 的 fetch_raw/fetch_rendered 分工）。框架直采（undici）无指纹伪装能力，被指纹墙挡的源一律分流推送，不在框架侧硬撞。
- **挑战系统**：Cloudflare Turnstile / DataDome / Akamai BMP 的共同点是「先评分再放行」：IP 信誉、UA 一致性、JS 执行环境、行为轨迹缺一扣分。本站 SCMP 走推送正是此理；巴伦四路均 403 如实跳过——识别「硬墙」并止损，比无限升级更重要。
- **政策型拦截（非技术墙）**：SEC EDGAR 无邮箱形态 UA 一律 403（2026-10-17 单变量实证：URL 串 403 / 浏览器 UA 403 / 邮箱形态 200）。这类「合规 UA」要求在各站开发者条款里，接入前先读条款再写代码；被 403 先分清是政策、指纹还是限流，不要一律升级隐身。
- **UA 与指纹一致性**：伪装时 UA、TLS 指纹、H2 序、语言头必须同属一个浏览器画像，混搭（如 Chrome UA + Python TLS）是最常见的人造破绽。

## 2. Scrapling 自适应与会话一致性（课题二）

- **自适应重定位**：Scrapling 的 adaptive 模式靠元素多维特征（文本/属性/结构路径）在页面改版后重找目标。本站 page 模式目前用「文章链接正则 + 日期」抽取（7 个 page 源实证稳定），改版风险点是链接规律而非选择器——链接正则失效的表征是「抓到 0 条或全是导航链接」，巡检应盯条数突变而非只看成败。
- **会话指纹一致性**：雪球源实证——必须先用 patchright 打开首页种 `xq_a_token` cookie，再在**同一上下文**调 API；跨上下文/跨 IP 混用 cookie 会触发风控。原则：一个源的预热、取数、翻页共用同一会话与出口，失败重建会话而不是换着试。
- **原始字节优先**：RSS XML / JSON 绝不能过浏览器渲染（会被包装成 HTML 致解析全灭，2026-10-17 已定版为框架规矩）；浏览器只用于 page 型列表页与 feed 型被墙 RSS 的兜底。

## 3. 时效工程（课题三）

- **轮询间隔按源分层**：快讯 5 分钟（框架 interval 或推送器快讯子集 cron）、常规新闻 30 分钟、EDGAR 30 分钟、arXiv 6 小时、日报窗口源按版。第一批实证：通过源单请求时延 0.6–2.2s（裸连），框架 egress 下东财 10s 级、arXiv 7.5s 级——间隔设定要留 ≥3 倍时延余量防堆积。
- **条件请求**：框架 RSS 已存 validator（ETag/Last-Modified，collect.ts cursor.rss），304 时跳过详情阶段；json_list 暂无条件请求支持。
- **News Sitemap / WebSub**：媒体站的 news sitemap（<news:publication_date>）是比 RSS 更准的时效面；WebSub（原 PubSubHubbub）为推送式更新，框架未接，列入观察不列入近期施工。
- **时间口径**：无时区时间按源时区读（默认 +08:00）是框架既定规矩；新源接入必须验一条「已知发布时间」的样本对齐（如东财 showTime 实测 +08 换算正确、披露易 DATE_TIME 按 HKT 读）。

## 4. 失败自诊断分类（课题四）

接入与巡检按六类归因，处置各异（第一批全部实证过）：

| 类 | 表征 | 本站实例 | 处置 |
|----|------|----------|------|
| DNS/SSRF 拦截 | `Blocked private address` | 新浪 zhibo 在沙箱 fake-IP 解析下被框架护栏拦 | 分流推送通道；生产正常 DNS 环境复核 |
| 政策 403 | 换 UA 形态即通/即死 | SEC 无邮箱 UA 403 | 读条款、按规矩申报，不硬撞 |
| 指纹/挑战 403 | 普通请求 403、隐身可过或全灭 | SCMP（可过）、巴伦（全灭） | 分级升级；全灭如实跳过并记录 |
| 空解析 | HTTP 200 但 0 条 | 巨潮 http+错参数曾返 total 0 | 先查参数口径（协议/字段/日期窗），再怀疑被封 |
| 嵌套/异形结构 | 200 且有数据但映射失败 | 披露易 result 为字符串化 JSON；EDGAR Atom 非 RSS item | 定制解析器走推送，不硬套 json_list |
| 表单编码不合 | 接口只收 form 不收 JSON | 巨潮 hisAnnouncement | 同上；json_list 的 bodyJson 只发 JSON，接入前先验编码 |

外加一类**链路抖动**：东财 collect 两次 fetch failed 后第三次成功——单次失败不下结论，fail_count 与退避是框架既有机制，巡检看趋势不看单点。

## 5. 58→64 源脆弱面清单（课题五）

- **推送依赖型（20 external）**：风险在推送器与 Mac 运行时（venv/浏览器二进制/token），不在框架；其中 page 型 7 源依赖目标站链接规律，改版即静默 0 条——巡检按源盯「近 24h 条数下限」。
- **被墙 RSS（feed 型推送）**：SCMP 依赖 Mac 直连可过、巴伦已全灭跳过；状态随目标站风控策略漂移，无预警。
- **框架直采（43 rss + 1 json_list）**：風險在 feed 地址变更/站点改版/出口链路；东财 json_list 是全站唯一 json_list 源，其 API 参数（fastColumn 等）为逆向所得，无官方承诺，列重点盯防。
- **讨论信号源（3）**：雪球 cookie 预热链最脆（平台风控敏感）；股吧/HN 依赖公开接口稳定性。
- **新源（6）**：巨潮日量 500+ 条靠「近 24h + 200/轮」限流，限流口径本身是脆弱点（漏抓风险与灌爆风险的平衡，S2 巡检观察后校准）；披露易 servlet 为未公开接口，参数口径可能随改版漂移。
